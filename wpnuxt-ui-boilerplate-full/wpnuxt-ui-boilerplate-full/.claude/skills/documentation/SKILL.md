# Skill: Documentation

## Purpose

Keep project knowledge synchronized with the implementation.

## Procedure

1.  Update the smallest relevant document when behavior/architecture
    changes.
2.  Keep `README.md` accurate for setup and commands.
3.  Keep `CLAUDE.md` as the live progress tracker.
4.  Update architecture/project structure for structural changes.
5.  Update content contract for CMS schema/view-model changes.
6.  Record meaningful tradeoffs in `docs/decisions.md`.
7.  Update testing, SEO, accessibility, performance, and workflow docs
    when their conventions change.
8.  Reconcile `docs/definition-of-done.md` before handoff.

## Rules

-   Documentation must describe the repository as it exists, not the
    intended future state.
