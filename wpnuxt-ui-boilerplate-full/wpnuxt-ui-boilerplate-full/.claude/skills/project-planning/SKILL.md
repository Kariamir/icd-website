# Skill: Project Planning

## Purpose

Plan the whole project before implementation and use `CLAUDE.md` as the
live progress monitor.

## Procedure

1.  Read `CLAUDE.md`, `docs/architecture.md`,
    `docs/project-structure.md`, `docs/workflow.md`, and
    `docs/definition-of-done.md`.
2.  Inspect the repository before proposing changes.
3.  Read `docs/frontend-requirements-intake.md`; identify missing or
    blocking inputs.
4.  Inventory pages, routes, UI sections, WordPress content types,
    integrations, SEO, accessibility, testing, and deployment needs.
5.  Define implementation phases and dependency order.
6.  Create or refresh the Project Progress Checklist in `CLAUDE.md`.
7.  Use `[ ]` for pending and `[x]` only after implementation plus
    validation.
8.  Record blocked/deferred work explicitly.
9.  At the start of later sessions, reconcile repository state with the
    checklist before continuing.

## Rules

-   Do not start broad implementation before the plan exists.
-   Do not silently perform untracked work.
-   Do not mark work complete because code exists; validation is
    required.
-   Add newly discovered required work to the checklist.
