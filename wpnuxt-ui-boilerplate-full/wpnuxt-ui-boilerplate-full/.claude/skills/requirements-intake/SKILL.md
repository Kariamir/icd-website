# Skill: Frontend Requirements Intake

## Purpose

Collect the inputs needed to implement the frontend without inventing
brand, UX, content, CMS, or delivery requirements.

## Procedure

1.  Inspect the repository, existing assets, WordPress structure, and
    documentation first.
2.  Read `docs/frontend-requirements-intake.md`.
3.  Determine what is already known.
4.  Ask only for missing information that materially affects
    implementation.
5.  Cover, as applicable: brand identity, logo variants, colors,
    typography/font files and licenses, Figma/designs, imagery, icons,
    motion, page list, responsive behavior, content, CTAs, WordPress
    models, ACF/Gutenberg, forms, integrations, SEO, analytics, consent,
    accessibility, browser support, hosting, deployment, and acceptance
    criteria.
6.  Separate blockers from assumptions and non-blocking unknowns.
7.  Feed confirmed requirements into the project plan and `CLAUDE.md`
    checklist.

## Rules

-   Never fabricate brand assets or requirements.
-   Do not ask for information already available in the project.
-   Prefer a short grouped questionnaire over many fragmented questions.
